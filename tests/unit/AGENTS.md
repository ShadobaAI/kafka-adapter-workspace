# Kafka Adapter unit-test workspace

Read the mandatory [workspace rules](../../WORKSPACE-RULES.md), [.ai/PROJECT.md](.ai/PROJECT.md) for ownership and [.ai/project.yaml](.ai/project.yaml) for profile mappings. Select `tests/unit` as the Codex working directory so these instructions and the profile apply; do not assume they are discovered when starting inside a nested Git repository.

- `unit` is the project-owned test extension. `base` is assembled from the adapter repositories: change the originals through the adapter project, then update the assembled copy using the existing script when authorized. `examples` is a checkout of adapter examples: change the original through the adapter project and update this checkout through Git when authorized. Do not make product fixes in these copies.
- `yaxunit` is an upstream framework checkout. Justified changes are permitted within task scope; preserve upstream conventions, keep Kafka-specific changes narrowly scoped, and leave changes uncommitted unless explicitly requested. Its framework role in the test workflow does not itself authorize a mutation. Run relevant focused upstream checks when available.
- EDT, code-index, BSL LS and v8std are mandatory for dependent 1C work. Use the unit EDT workspace for all four projects; stop dependent work when exact mappings or services are unavailable. Do not duplicate its connection in sibling projects or user configuration.
- Use only `kfk-unit` for `unit`, `kfk-yaxunit` for the upstream framework, canonical `kfk-base` and `kfk` for assembled base, and `kfk-examples` for examples. Do not separately index the base or examples copies, substitute an alias for the framework or let index selection change the EDT route.
- `examples` is a development-only extension and is not a production artifact. Run relevant adapter scenarios covering a change when available. Assembly scripts and non-1C configuration may be edited directly in UTF-8 within scope; never manually edit generated EDT projects, reports, or test output.
- Apply YAxUnit naming requirements to test modules; use `кфк_т_` for new objects owned by examples. Preserve Russian 1C identifiers.
- Use focused EDT diagnostics and relevant focused YAxUnit checks; report unavailable checks. Before introducing reusable behavior, check existing facilities and justify solution complexity at design and review.
- OpenViking is an optional, preferred source for adapter documentation when ready; its lifecycle and publication are external. It does not replace EDT or v8std.
