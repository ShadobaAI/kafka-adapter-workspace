# 1С: Адаптер Kafka — рабочее пространство

Рабочее пространство для разработки [1С: Адаптер Kafka](https://github.com/ShadobaAI/kafka-adapter), его интеграций и тестов. [Корневой репозиторий kafka-adapter-workspace](https://github.com/ShadobaAI/kafka-adapter-workspace) предназначен для общей структуры, инструкций и переносимых AI-профилей; исходный код проектов хранится в независимых репозиториях.

## Документация

Руководство пользователя, примеры и справочник API доступны на [сайте документации адаптера](https://shadobaai.github.io/kafka-adapter/). Рабочие инструкции расположены в [AGENTS.md](AGENTS.md), [WORKSPACE-RULES.md](WORKSPACE-RULES.md) и [1C-RULES.md](1C-RULES.md).

Вложенные репозитории подключаются отдельно и сохраняют собственные истории Git; корневой репозиторий не является их заменой. Файлы `.gitkeep` сохраняют каталоги, в которых нет других отслеживаемых корнем файлов, но не содержат исходный код проектов.

При восстановлении рабочего пространства сначала клонируйте корневой репозиторий, затем отдельно получите нужные вложенные репозитории. Git не клонирует репозиторий прямо в непустой каталог: сохраняйте `.gitkeep` и другие уже размещённые корнем файлы, клонируйте вложенный репозиторий во временный каталог и переносите его содержимое и `.git` в целевой каталог после проверки совпадающих путей. Не перезаписывайте корневые AI-файлы; для чистого восстановления вложенные репозитории должны содержать изменения, исключающие их прежние AI-файлы. В `conversion/КД` и `tests/unit/base` дополнительно нужны соответствующие внешняя и собранная конфигурации.

## AI-профили

AI-harness рабочего пространства — плагин [1C AI Core](https://github.com/ShadobaAI/edt-ai-core) для Codex. Он использует контекст и профили проектов для работы с EDT, анализа кода, проверки стандартов и тестирования.

Для работы с 1С используются профили [adapter](adapter/.ai/project.yaml), [conversion](conversion/.ai/project.yaml), [unit](tests/unit/.ai/project.yaml) и профиль UI в `tests/ui/.ai/project.yaml`. Для каждого проекта выбирайте его рабочий каталог и следуйте местным инструкциям. EDT, code-index, BSL LS и v8std необходимы в соответствии с правилами выбранного профиля; OpenViking используется как необязательный источник документации при доступном внешнем сервисе.

Инструкции и настройки, необходимые внутри каталогов `tests/ui`, `tests/reports`, `tools` и `tasks`, хранятся в корневом Git, но остаются по своим рабочим путям. Вложенные `.gitignore` исключают их из соответствующих репозиториев.

## Локальные данные

Корневой [.gitignore](.gitignore) ограничивает добавление новых файлов; уже отслеживаемые файлы внутри вложенных репозиториев принадлежат корневому Git. Вложенные репозитории, базы и результаты работы, индексы, секреты, персональные настройки, резервные копии и локальные экземпляры профилей не должны попадать в корневой Git. Локальная `.migration-backup/` содержит сохранённые версии заменённых старых инструкций и настроек; она не отслеживается.

Обычный `git add` не обнаруживает новые файлы внутри вложенного Git-репозитория. Уже отслеживаемые корневым Git файлы можно изменять и добавлять в индекс обычным `git add -u`.
